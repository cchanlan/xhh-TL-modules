# 小火花功能模块

这是 [xhh-TL](https://github.com/cchanlan/xhh-TL) 的独立模块源码和下载包仓库。不要把本仓库克隆到 Yunzai 的 plugins 目录；在锅巴 → 小火花模块中心 → 模块管理选择安装。

## 使用

安装、更新、卸载均在重启机器人后生效。卸载保留用户配置、账号、订阅和记录；可选图库与业务功能分别安装。依赖包由管理器自动处理，不需要手动安装共享代码。

模块下载跟随核心的仓库来源：**Gitee → Gitee、GitCode → GitCode、GitHub → GitHub**，不需要另选模块源。请更新小火花核心后使用。

## 开发

- `modules/<id>/module.json`：功能信息、依赖、入口与源码文件白名单。
- `modules/<id>/files/`：源码/模板/资源，保持相对于核心安装根目录的路径。
- `scripts/build.mjs`：执行 `node scripts/build.mjs`，生成不可变版本包与目录。
- `catalog.json`：模块元数据、精确依赖版本、文件归属及 SHA-256。
- `packages/<id>/<version>.xhmp`：gzip 压缩 JSON，文件以 base64 存储。没有安装脚本、符号链接和归档路径解释。
- `packages/<id>/<version>.xhmp.parts/0001.part`：原包的固定512 KiB连续分片，最后一片可更短；Gitee大包按序下载并合并，仍校验原整包SHA-256。分片格式固定，不随操作系统或构建机版本改变。

构建会为当前及历史整包补齐分片；不覆盖已发布整包或不一致的分片，不改原目录/版本/哈希。旧缓存目录没有额外分片字段也能恢复下载。

每个文件仅归属一个模块；共享库必须在 dependencies 声明。改变共享库会传播依赖版本，更新时管理器会同步准备受影响的已安装模块。已发布版本包不可覆盖；旧包需保留供旧核心安装/恢复。

发布先推本仓库、核验公开包可下载与 SHA-256，再更新核心目录快照和发布核心。模块运行时写数据仍使用核心原有 data/config；这些内容永不入库。不要把服务端私有代码、用户素材、CK 或 Token 放进模块源码。

## 兼容与许可

沿用 Yunzai 生态接口，兼顾 JiuLi；业务 API 不因拆包改变。当前测试使用 Linux 上隔离宿主与锅巴实际前端；不是 Windows 或所有框架实跑认证。

插件源码沿用 MIT（见 LICENSE）；原第三方资源及引用保留原作者权利，资源来源说明和过码服务许可边界见主仓库 README。独立过码服务仍来自主仓库 solver 分支，不随此模块仓库分发。

鸣潮体力 `waves` 依赖 `tl` 提供查询指令，并依赖 `shared_sqlite` 读取账号数据；依赖变更须重建包和同步核心目录，不能只改核心快照。

## 核心版本契约

当前目录 coreApi=2，最低核心版本 2.1.0，最低 Node 18.17.0。业务代码调用的新核心工具由此契约约束，不向旧 coreApi=1 发布兼容假象。构建版本哈希包括核心契约和宿主依赖标记。旧客户端必须先更新核心。
